⚙️ Diferenciais técnicos comprovados no README
Eclusa Stateless (JWT)
Login emite token assinado HMAC256. API valida sem tocar o banco — escalabilidade horizontal instantânea.
SecurityFilter customizado

BCrypt + Tratamento Global
Senhas nunca em texto plano. GlobalExceptionHandler blinda metadados, evita Information Disclosure.

Frontend reativo seguro
React/Next.js intercepta 401 do backend e protege rotas no client. Demonstração visual completa: 12 telas no README.
OpenAPI / Swagger desacoplado
Metadados isolados em br.com.safewallet.doc.controllers (Clean Architecture). JSON portátil para Postman/Insomnia.

S2-S5 · 4 semanas

🧠 LRU Cache Engine

Java puro · DSA manual · Big O O(1) · 10k ops validadas

Estrutura de dados manual — sem java.util — construída em camadas ao longo de 4 semanas. Diferencial raro em Jr para entrevistas de big tech.

📋 Construção em camadas:
  • S2 ▸Node<K,V> + DoublyLinkedList: addToHead() em O(1), removeNode() reajustando ponteiros, removeTail() em O(1) retornando o ejetado
  • S2 ▸JUnit 5: testar lista vazia, remoção do head/tail/meio, validar size em cada operação — zero NPE
  • S3 ▸BST manual: insert() recursivo, search() binário em O(log n), traversals (In-Order/Pre-Order/Post-Order)
  • S3 ▸HashMap manual com Chaining: função hash customizada, array de buckets, put() e get() em O(1) médio
  • S4 ▸LRU Cache (fusão): HashMap + DoublyLinkedList, capacity no construtor, put/get O(1), removeTail quando size > capacity
  • S4 ▸Active Recall total: 4 folhas no caderno (DLL + HashMap + BST + LRU) reproduzidas de cabeça
  • S5 ▸Stress test: 10.000 operações JUnit, validar O(1) real, medir tempo, cache hit vs miss
  • S5 ▸README inglês: análise Big O explicada, repositório independente como showcase
  • S7 ▸Maratona DSA: reproduzir tudo de cabeça + Feynman ("explicar por que O(1)")
🎯 Entrega: LRU Engine validado com 10k ops + Big O em inglês no README
